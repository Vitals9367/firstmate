## Coding guidelines

Follow these guidelines in every project, except for changes to the firstmate repository itself, which follows its own contributor guidelines.

- Naming: use Clean Code names. Variables, classes, functions, and files get descriptive names that say exactly what they hold or do.
- Functions: each function does one thing only, where possible.
- Comments: write no comments in code.
- Tests: write no tests unless the task explicitly asks for them. If a validation review asks for tests the task did not request, do not add them; report it as a decision for firstmate instead.
- Wording: write all prose (docs, PR descriptions, commit messages) roughly 80% to ASD-STE100 Simplified Technical English (https://www.asd-ste100.org/): short sentences, simple approved words, one meaning per word, active voice.
- PR size: split a larger feature into a stack of dependent PRs of roughly 500 changed lines each, rather than one big PR.
